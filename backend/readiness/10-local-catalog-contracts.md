# U03/B004 local catalog contracts

**Scope:** BUILD-009 through BUILD-013, DEV-PHYSICAL-BD revision 1. [B004 evidence](../../context/aidlc/bolts/B004-catalog.md) owns actual verification; human acceptance remains pending. [OpenAPI JSON](../openapi/catalog-v1.json) is the executable initial catalog contract, also served at `/api/v1/openapi.json` on the private loopback API.

## API and authorization

All routes use prefix `/api/v1`. Staff requires B003 signed local MFA and current PostgreSQL grants. `catalog.edit` controls staff list/detail, drafts, variants, prices and media links; `catalog.publish` controls publication/unpublication/archive. Existing catalog_editor contains both; access_admin alone cannot read/edit catalog. No caller header or old response grants permission. Anonymous public reads contain only current published facts and always use no-store.

Every catalog POST/PATCH requires UUID `Idempotency-Key`. Existing product and child changes additionally require quoted product aggregate `If-Match`, e.g. `"5"`. Responses use exact decimal strings for versions/money. Child responses include productVersion, and their ETag is that product version. Variant/price version is a separate returned fact, not the expected product precondition. Missing precondition 428, malformed/unknown input 400, missing identity 401, current permission denied 403, missing/hidden resource 404, stale version 412, conflict 409, publication/reference requirements 422, unavailable database/unknown commit 503. Problem bodies have safe fixed details and fresh correlation IDs.

| Operation | Route | Behavior |
| --- | --- | --- |
| Create/list products | POST/GET /staff/catalog/products | Create draft only; bounded keyset list by UUID, optional status filter |
| Detail/edit draft | GET/PATCH /staff/catalog/products/{id} | Minimal staff detail including at most 50 variants, 100 latest price records and 20 media links; draft edits only |
| Create/edit variant | POST /staff/catalog/products/{id}/variants; PATCH /staff/catalog/products/{id}/variants/{variantId} | Product draft required; exact owner predicate; immutable SKU identity |
| Archive variant | POST /staff/catalog/products/{id}/variants/{variantId}/archive | Product draft required; retains SKU and price facts |
| Schedule price | POST /staff/catalog/products/{id}/variants/{variantId}/prices | Positive BDT/web price; explicit effective interval and staff attribution; product/variant eligibility locks |
| Close price | POST /staff/catalog/products/{id}/variants/{variantId}/prices/{priceId}/closure | Future effective endpoint; retain amount/start/actor facts; cannot extend or revise an already ended interval |
| Attach approved fixture media | POST /staff/catalog/products/{id}/media | Draft product; existing approved media metadata; optional same-product variant; bounded primary/order/alt fields |
| Publish/unpublish/archive | POST /staff/catalog/products/{id}/publication, /unpublication, /archive | catalog.publish plus reasonCode/product version; publication guard; terminal archive |
| Published detail | GET /store/products/{slug} | Anonymous minimal current product/media/variant/attribute/price representation; unpublished/ineligible returns 404 |

Product fields: title 1–200, normalized lowercase slug 1–160 (letters/digits separated by single hyphens), optional shortDescription up to 1,000, description up to 20,000, nullable brandId, unique ordered categoryIds up to 20 (first is primary). Descriptions are plain text: angle brackets and control characters rejected. Optional description fields may be null. After first publication, slug cannot change. To edit previously published content, unpublish, edit the draft, then republish. This slice does not claim an order snapshot implementation.

Variant fields: ASCII SKU 1–64 (letters/digits/dot/underscore/hyphen), normalized uppercase before command hashing; title 1–200; optional barcode up to 64, integer maxOrderQuantity 1–20, positive integer weightGrams, at most 20 unique attribute selections. Attribute/value ownership is checked with composite FKs. SKU is immutable and unique across archived rows. Product cap is 50 variants including archived records; this explicit fixture bound is not a measured merchant capacity. Categories/brands/attributes are reference metadata created by the guarded fixture; category reparenting is deliberately unsupported and cannot create cycles.

Prices use decimal strings 1 through 9223372036854775807. Numeric JSON, fractions, leading zeros, negatives and excess range are rejected. compareAtMinor is nullable and cannot be below unitPriceMinor. Currency/channel are server-fixed BDT/web. ISO instants require millisecond UTC form, e.g. `2030-01-01T00:00:00.000Z`. Intervals are `[validFrom, validTo)` with nullable unbounded end. A PostgreSQL GiST exclusion using the trusted btree_gist extension prevents overlaps per variant/currency/channel, including direct concurrent inserts. [PostgreSQL range constraints](https://www.postgresql.org/docs/18/rangetypes.html#RANGETYPES-CONSTRAINT) informed this implementation; local database tests supply actual evidence. Historical amounts/identity/start/attribution cannot be updated. Closing an active/future interval can leave a deliberate future availability gap; public reads and later checkout must recheck the current interval.

## Publication and public reads

Publication requires nonblank product description, at least one category, every assigned category and ancestor published, an active brand if selected, at least one non-archived variant, active attribute selections, a current price for every non-archived variant and at least one primary product-level approved image with nonblank alt text. These stricter local completeness rules ensure all live variants are priced when published. Publishing promotes non-archived variants; unpublishing returns them to draft; archiving retains source rows and makes the product terminal.

Public detail uses one repeatable-read PostgreSQL snapshot and one database timestamp. It rechecks publication prerequisites, approved media and effective prices; prior public/index data is never authority. It excludes raw object keys, staff identities, internal histories/versions, unapproved media, draft/archived variants and stock counts. `indicativeAvailability` is explicitly `unknown` because U04 stock does not exist. Returned `/synthetic-media/...` paths are fixture metadata, not a deployed media delivery service or evidence of image scanning; BUILD-030 owns actual private upload/inspection/public delivery. A request already reading a valid snapshot can finish while a concurrent archive commits; new reads observe the archive.

Staff list has limit 20 by default/100 maximum, ascending UUID keyset order and an opaque base64url cursor bound to status and limit. Malformed cursors, mismatched filters and unknown query fields fail. Cursor contents are not secret and do not grant access. There are no unbounded totals. Staff detail intentionally shows only the latest 100 price records; full history remains in PostgreSQL for later governed queries.

## Transactions, replay and event ownership

Lock order: scoped idempotency advisory lock; current identity access lock `(2002,1)`; idempotency row; product row; variant rows in UUID order when multiple apply; dependent metadata. Identity revocation uses the same access lock and remains effective for commands admitted after it commits. No external call occurs under these locks. This retains B003's conservative local access serialization; no throughput claim is made. Later checkout must acquire compatible product/variant eligibility locks before accepting price/publication facts.

The canonical hash covers validated input and expected product version. Object property order is insignificant; SKU normalization occurs first; ordered categories stay ordered. Scope includes staff actor, surface and operation/resource. Replays first reauthorize current grants. Same key/hash returns the stored safe status/body/Location and version with `Idempotency-Replayed: true`, even if the aggregate has subsequently changed. Different payload/version under the key returns 409 IDEMPOTENCY_MISMATCH. This does not retry or apply a new edit. Completed outcomes are immutable; seven-day expiration rejects reuse and no purge/reuse worker exists.

Successful changes and deterministic in-transaction 400/404/409/412/422 outcomes are stored. Validation before admission and permission denials do not create command records. A savepoint rolls back all tentative business/audit/outbox work before recording a deterministic failure. Internal errors, lock/connection failures and uncertain commits are not converted into successful results or blindly retried. A lost COMMIT response returns COMMIT_UNKNOWN; resubmitting the exact authorized key/payload resolves the committed snapshot, or performs the command only if the original transaction left no record/effect. Tests inject reply loss after a real COMMIT; no managed failover claim.

Every successful catalog command increments the product aggregate (create starts at 1), writes protected audit and one outbox event plus its fixed routing-version-1 `search-projection` delivery. Event names are product.created/changed/price_changed/published/unpublished/archived. Payload contains only product ID, product version and status; event/aggregate/routing schema versions, producer, correlation and UTC times are stored separately. Price/variant changes deliberately increment this product aggregate so catalog events share one ordering domain. Inventory will retain its own aggregate versions in later Units.

Delivery state remains pending. `capture-catalog-events.cjs` reads the last 100 local event/destination rows to an ignored artifact without publishing or marking them. No dispatcher, consumer receipt/effect, search projection, queue or cache is implemented here; BUILD-027/029 own those outcomes. All destinations are fixed atomically when the event is created, supporting later delivery progress without reconstructing routing from current configuration.

## Schema and compatibility

0002_catalog adds 13 catalog tables and idempotency_records/outbox_events/outbox_deliveries. Existing audit rows and original fields are preserved. New actor_type/actor_customer_id/target_schema/target_table/reference metadata provides staff/customer actor consistency. Generated aliases change_summary/reason_code/occurred_at retain compatibility with B003 summary/reason/created_at writers without copying divergent values. Existing defaults target IAM staff accounts; catalog writers explicitly target catalog/products. Other actor kinds require later reviewed extension. Runtime can append audit but cannot read/rewrite/delete it; outbox insertion does not grant history mutation. Fixture/reference/media/content writes remain migrator-only. Content revision schema protects already published rows; the content publication workflow remains BUILD-030.

There are now 24 implemented logical tables (eight from B003, sixteen new); 54 of the 78 proposed tables remain future work. The migration installs btree_gist in the catalog schema, using the local database-owner migrator. No production extension/migration approval is implied. Existing migration bytes stay immutable. Fresh build and upgrade must use the three-revision application readiness identity; old B003 readiness rejects the additional revision. Preserve evidence on rollback and use compatible/forward application fixes. Arbitrary live table/index drift detection and full generated Drizzle model snapshots remain future work.
